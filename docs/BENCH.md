# Бенчмарки: `cii bench`

Команда отвечает на вопрос «что это за машина и какой у неё канал». Идеи взяты из [masonr/yet-another-bench-script](https://github.com/masonr/yet-another-bench-script) и [teddysun/across](https://github.com/teddysun/across) (bench.sh), но всё реализовано заново на Go внутри сетевой политики cii: ничего не скачивается, результаты никуда не отправляются, каждый адрес объявлен заранее и виден в `--plan`.

```bash
cii bench
```

```bash
cii bench --servers ru --duration 10s
```

```bash
cii bench --no-disk --no-cpu --servers "iperf.example.net:5201-5209:MyISP:Frankfurt"
```

```bash
cii bench --system
```

Флаги команды: `--no-disk`, `--no-cpu`, `--no-speed`, `--no-iperf` отключают части; `--disk-dir DIR` и `--disk-size SIZE` (по умолчанию временный каталог и `1G`, минимум 64 МиБ) задают файл дискового теста; `--duration DUR` (по умолчанию 5s; целое число секунд от 1s до 1m) — длительность каждого сетевого замера; `--servers LIST` выбирает iperf3-серверы; `--system` дополнительно запускает установленные iperf3 и fio. Общие флаги cii (`-4`/`-6`, `--iface`, `--source`, `--proxy`, `--timeout`, `--offline`, `--json`, `--debug`, `--mask`, `--no-log`) работают как обычно; `--offline` оставляет только систему, диск и CPU. Без `-4` и `-6` сетевые замеры идут по IPv4, чтобы числа разных запусков были сопоставимы; на машине только с IPv6 нужен `-6`.

## Сведения о системе

На Linux читаются `/proc/cpuinfo` (модель, флаги `aes`, `vmx`/`svm`), `/proc/meminfo`, `/proc/uptime`, `/proc/loadavg`, `/proc/sys/kernel/osrelease`, `/etc/os-release` и DMI в `/sys/class/dmi/id` для определения виртуализации (KVM, VMware, VirtualBox, Hyper-V, Xen, GCE, EC2, OpenStack, Parallels, bhyve, контейнер по `/proc/1/cgroup`, OpenVZ). На других системах — только ОС, архитектура и число процессоров.

## Диск

Файл `.cii-bench-<случайный суффикс>` создаётся в `--disk-dir` только как новый (`O_EXCL`, на Windows `CREATE_NEW`): существующий файл или символическая ссылка с таким именем не используются. После теста файл удаляется. Нужно вдвое больше свободного места, чем размер файла. Открывается с прямым вводом-выводом: `O_DIRECT` на Linux, `F_NOCACHE` на macOS, `FILE_FLAG_NO_BUFFERING | FILE_FLAG_WRITE_THROUGH` на Windows; если это не удалось, тест идёт через кэш и в выводе помечается «buffered». Замеры:

| Тест | Как | Что показывается |
|---|---|---|
| seq | последовательная запись файла блоками 1 МиБ, `fsync`, затем последовательное чтение | МБ/с на чтение и запись |
| 4k, 64k, 512k, 1m | 4 секунды случайного чтения и записи поровну, 8 параллельных потоков со своим xorshift-генератором смещений | МБ/с и IOPS на чтение и запись |

Ошибка чтения или записи в любом из замеров прекращает дисковый тест: вместо чисел в заметках появляется строка `disk: …`.

Числа сопоставимы между запусками cii на разных машинах, но не с fio напрямую: другая очередь и модель нагрузки. Для сопоставления с привычными цифрами есть `--system`.

## CPU

Три нагрузки на реальных примитивах из стандартной библиотеки Go, каждая по 1,5 с на буфере 1 МиБ: SHA-256, AES-256-GCM и deflate (уровень по умолчанию). Буфер заполняется псевдослучайным текстом из словаря в 512 слов: он сжимается примерно как обычный текст, поэтому deflate выполняет настоящую работу, а не сворачивает повторяющийся узор. Сначала один поток, затем столько, сколько процессоров видит Go. Показываются пропускные способности в МБ/с и сводный балл: `(sha256 + aes_gcm + 4·deflate) / 1000 МБ/с · 100`. Балл свой, с чужими бенчмарками не сравнивается; AES без аппаратной поддержки будет заметно медленнее, что и видно в выводе рядом с флагом AES-NI.

## Скорость через Cloudflare

Используется публичный speed-тест Cloudflare на `speed.cloudflare.com`: пять запросов `/cdn-cgi/trace` дают задержку (лучшая из пяти) и код дата-центра, затем `--duration` секунд скачивания `/__down?bytes=N` с удвоением размера от 1 МиБ до 50 МиБ и столько же отправки нулей в `/__up` (от 256 КиБ до 25 МиБ). Блок растёт, только пока предыдущий уложился в четверть оставшегося времени. Скачивание обрывается ровно по истечении `--duration`, и принятая часть последнего блока учитывается; при отправке считаются только блоки, принятые сервером целиком, а на завершение последнего даётся до 10 секунд сверх `--duration`. Скорость — это переданные байты, делённые на время самих передач: для скачивания от первого байта тела ответа, для отправки на весь запрос.

Cloudflare ограничивает объём на адрес и на превышение отвечает HTTP 403. После такого отказа cii больше не запрашивает блоки этого размера (потолок опускается вдвое), делает паузу от 250 мс до 1 с и продолжает; отказанные запросы в скорость не входят. Ошибка показывается, только если за всё время не прошёл ни один блок. Запросы идут через `netx.HTTPClient` с обычным User-Agent cii и через прокси, если он задан.

## iperf3

Собственный клиент протокола iperf3 (контрольный поток, cookie, обмен параметрами и результатами в JSON, четыре параллельных потока по умолчанию). Сначала отправка, через секунду приём (`reverse`). Порты из диапазона перебираются по очереди: занятый сервер (`server busy`, коды 10 и 11), отказ в доступе, неудачное соединение и молчание сервера в первые 5 секунд после соединения переводят к следующему порту; любая другая ошибка прекращает попытки для этого сервера. Длительность теста — `--duration`.

При прокси (флаг или окружение) iperf3 пропускается с пометкой: иначе сырой TCP ушёл бы мимо прокси. С `-6` используются только серверы с IPv6.

Списки серверов (`--servers`, через запятую):

| Набор | Серверы |
|---|---|
| `global` (по умолчанию) | Clouvider Лондон и Лос-Анджелес, Eranium Амстердам, Uztelecom Ташкент, Leaseweb Сингапур и Нью-Йорк — публичные серверы из списка YABS, все с IPv6 |
| `ru` | Hostkey Москва; Дом.ру (Ertelecom): Санкт-Петербург, Нижний Новгород, Казань, Ростов-на-Дону, Екатеринбург, Новосибирск, Иркутск |
| `all` | оба набора |
| `host:ports[:provider[:location]]` | свой сервер, например `iperf.example.net:5201-5209:MyISP:Frankfurt`; IPv6-адрес пишется в скобках: `[2001:db8::1]:5201` |

Наборы и свои серверы можно смешивать (`ru,iperf.example.net:5201`); повторы убираются. Порты — число или диапазон в пределах 1–65535. Запись, которую не удалось разобрать, — ошибка: `cii bench` завершается до начала замеров. Свой сервер считается доступным и по IPv4, и по IPv6, так что с `-6` он тоже проверяется.

Российский набор собран вручную: взяты операторские speedtest-площадки, которые годами держат публичные iperf3-порты, по одной на крупный город и федеральный округ. Список [itdoginfo/russian-iperf3-servers](https://github.com/itdoginfo/russian-iperf3-servers) использован как подсказка, какие площадки живы и какие у них порты (у некоторых серверов Дом.ру часть портов закрыта, отсюда диапазоны вроде `5202-5209`). Если оператор закроет сервер, он выпадет из списка при следующем обновлении; свой сервер всегда можно указать явно.

## Установленные программы: `--system`

По флагу `--system` cii дополнительно запускает уже установленные `iperf3` и `fio` и показывает их результаты рядом со своими (строки `[iperf3]` и `fio`). cii ничего не скачивает: если программы нет, в заметках появляется команда установки для вашей системы (`apt`, `dnf`, `apk`, `pacman`, `opkg`, `zypper`, `pkg`, `brew`, `winget`). Системный iperf3 вызывается с теми же серверами, портами, числом потоков, длительностью, семейством адресов и адресом источника; перед запуском хост проходит ту же сетевую политику (`netx.LookupHost`), и соединение записывается в журнал контактов. fio получает те же четыре профиля (`seq-1m`, `rand-4k`, `rand-64k`, `rand-512k`; `direct=1`, глубина очереди 64, два задания) на файле `.cii-fio-<случайный суффикс>` в `--disk-dir`, который cii сам создаёт как новый и удаляет после теста.

Ookla Speedtest CLI не подключается: его лицензионное соглашение cii за пользователя принять не может. Geekbench и подобные инструменты, которые сами отправляют результаты, исключены политикой.

## Вывод

В компактном режиме — строки `System`, `Disk`, `fio`, `CPU`, `Speed`, `iperf3` и заметки; в `--debug` — таблицы по каждому разделу и журнал контактов; в JSON — объект `bench` со всеми числами (байты, МБ/с, IOPS, мс), длительностью и заметками. Как и остальные команды, `cii bench` пишет локальный лог.
