# Архитектура

## Принципы

- Один статический бинарник Go (`CGO_ENABLED=0`): Linux amd64/arm64/arm/386/mips/mipsle/riscv64, macOS amd64/arm64, Windows amd64/arm64.
- Вся сеть идёт через `internal/netx`: политика + журнал. Подробности — в [NETWORK_POLICY.md](NETWORK_POLICY.md).
- Справочники, которые можно распространять, встраиваются в бинарник. Крупные базы лежат в каталоге данных и обновляются только явной командой.
- Собственные реализации там, где это разумно (iperf3-клиент, DNS/DoH/DoT, MTProto-проба, дисковый и CPU-тесты). Внешние программы — только если они уже установлены пользователем и по флагу. cii их не скачивает, а при отсутствии подсказывает команду установки для вашего дистрибутива.
- Прозаические пояснения живут в `docs/`, код — без поясняющих комментариев.

## Пакеты

| Пакет | Назначение |
|---|---|
| `cmd/cii` | CLI: разбор флагов, подкоманды, сборка отчёта; сессия запуска с частичными результатами (`session.go`) и живой экран в альтернативном буфере терминала (`screen.go`), на Windows — с включением обработки ANSI-последовательностей |
| `internal/netx` | `Policy` (allowlist по модулям, точные хосты и `*.suffix`), `Net` (HTTP-клиент с guard на каждом запросе и редиректе), выбор семейства IP, привязка к адресу или интерфейсу, прокси |
| `internal/ledger` | Журнал соединений: модуль, назначение, хост, протокол, число запросов, ошибок и блокировок |
| `internal/ipdetect` | Публичные адреса: интерфейсы, затем echo-сервисы по порядку (форматы `plain`, `trace`, `json:поле`), с проверкой семейства ответа |
| `internal/geodb` | Поиск по локальным `.mmdb` (схемы GeoIP2/DB-IP и IPinfo Lite приводятся к одному `Record`), атрибуция по лицензиям |
| `internal/datasrc` | Реестр баз (ID, лицензия, хосты, нужен ли ключ), загрузка с проверкой формата mmdb, атомарная замена файла, `manifest.json` с sha256 |
| `internal/probe` | Общий движок проверок: `Check` (запросы, уровень A/B, ключ пользователя, функция оценки), запуск с ограничением параллельности через `netx`, извлечение данных (JSON-путь, регулярки, заголовки), `Select` и правила политики |
| `internal/region` | Каталог проверок региона и вердикт с равным весом групп. Перечень — в [REGION_CHECKS.md](REGION_CHECKS.md) |
| `internal/services` | Каталог проверок доступности сервисов. Перечень — в [SERVICE_CHECKS.md](SERVICE_CHECKS.md) |
| `internal/risk` | Репутация адреса (keyless proxycheck.io + платные базы с ключом пользователя), DNSBL с правилами FUP через `netx.LookupHost`, проба SMTP через `netx.Dial`, офлайн-списки Tor и облаков со своим манифестом. Перечень — в [RISK_CHECKS.md](RISK_CHECKS.md) |
| `internal/censor` | `cii censor`: собственный DNS по UDP/DoH/DoT, детектор подмены, веб-проверки с `httptrace`-фазами, MTProto-рукопожатие Telegram — всё через `netx`. Перечень — в [CENSOR_CHECKS.md](CENSOR_CHECKS.md) |
| `internal/bench` | `cii bench`: сведения о системе из `/proc` и `/sys`, дисковый тест с прямым вводом-выводом, CPU-тест, скорость через Cloudflare, собственный iperf3-клиент; установленные iperf3 и fio — по флагу. Описание — в [BENCH.md](BENCH.md) |
| `internal/clientids` | Все сторонние идентификаторы клиентов, нужные проверкам уровня B, в одном месте |
| `internal/refdata` | Встроенные справочники: названия стран (CLDR) и «IATA → страна» (OurAirports); генерируются `go generate ./internal/refdata` |
| `internal/config` | Необязательный `config.yaml`: свои ключи, свой список echo-сервисов, набор баз по умолчанию |
| `internal/report` | Кадр основного запуска в одну, две или три колонки по ширине окна (`screen.go`, `profile.go`), компактный вывод `lookup`, `censor` и `bench` (`compact.go`), подробные таблицы для `--debug` и лога (`probes.go`, `report.go`), JSON, маскирование адресов, план, журнал; выравнивание по видимой ширине с учётом цвета (`grid.go`) |
| `internal/runlog` | Локальный лог каждого запуска: подробный отчёт + JSON, права 0600, хранятся последние 20 |
| `internal/paths` | Каталоги конфига, данных и логов по ОС (XDG, `%LOCALAPPDATA%`, `~/Library/…`) |

## Поток выполнения `cii`

1. Загрузить конфиг (если есть) и собрать политику из правил модулей.
2. При `--plan` — напечатать правила и выйти.
3. Открыть все `.mmdb` из каталога данных.
4. Для каждого семейства (IPv4, IPv6): определить адрес, найти записи во всех базах.
5. Для каждого найденного адреса — проверки региона и сервисов (если не `--quick` и не `--offline`; уровень B — только с `--extended`); локальные базы участвуют в вердикте как мнения группы GeoIP.
6. Приложить журнал соединений и вывести отчёт.

## Отчёт (`--json`, схема `cii.report/v1`)

| Поле | Содержимое |
|---|---|
| `schema`, `tool`, `generated_at`, `mode` | метаданные (`mode`: `online`, `offline`, `lookup`) |
| `ipv4`, `ipv6` | `address`, `source` (`echo:<провайдер>` или `interface`), `interface[]`, `error`, `geo[]`, `region` |
| `region` | `verdict[]` (одна страна или несколько при равенстве), `results[]`, `attention[]` |
| `services` | список результатов |
| результат проверки | `group`, `service`, `status` (`ok`, `yes`, `no`, `partial`, `unknown`, `ipblock`, `error`), `country`, `iata`, `node`, `reason`, `extended` |
| `results[]` | то же для `cii lookup`, плюс `query` |
| `geo[]` | `source`, `network`, `country`, `country_name`, `registered_country`, `continent`, `region`, `city`, `latitude`, `longitude`, `asn`, `as_org`, `as_domain` |
| `data[]` | использованные базы: `id`, `type`, `built` |
| `attribution[]` | строки атрибуции, которых требуют лицензии баз |
| `network[]` | журнал соединений; для DNS-запросов и сырых соединений по правилу с маской в `host` записывается сама маска (`*.zen.spamhaus.org`), а не запрошенное имя: в DNSBL-запросе оно содержит проверяемый адрес |
| `masked` | были ли адреса замаскированы (`--mask`) |

## Будущие модули

Каждый модуль объявляет свои правила политики, работает через `netx` и добавляет раздел в отчёт.

| Модуль | Источник идей | Суть |
|---|---|---|
| `services` | RegionRestrictionCheck, IPQuality, ipregion | доступность стримингов, ИИ-сервисов, CDN по регионам; декларативный каталог (YAML) + Go для сложных случаев, уровни A/B |
| `bench` | YABS, bench.sh, russian-iperf3-servers | iperf3 (свой клиент), скорость через Cloudflare, сведения о системе, диск, CPU |
