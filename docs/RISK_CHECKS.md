# Репутация адреса, DNSBL и почта

Модуль `risk` отвечает на вопрос «как этот адрес выглядит со стороны»: считают ли его VPN, прокси или дата-центром, числится ли он в чёрных списках рассылок, открыт ли исходящий 25-й порт, входит ли он в известные диапазоны Tor и облаков. Источники идей — [xykt/IPQuality](https://github.com/xykt/IPQuality) и его список DNSBL; в отличие от оригинала, ничего не идёт через серверы автора, а платные базы работают только с вашими ключами. Отключается флагом `--no-risk`; в режиме `--offline` остаётся только офлайн-часть.

Статусы: `yes` — чисто, `no` — есть флаги или адрес в списке, `partial` — адрес в диапазоне облака или CDN (это не плохо, но для многих сервисов такой адрес «серверный»), `?` — источник недоступен или не ответил по существу, `!` — ошибка.

## Репутация (группа Reputation)

| Сервис | Ключ | Запрос | Как читается |
|---|---|---|---|
| proxycheck.io | не нужен; `proxycheck_key` снимает дневной лимит | `GET proxycheck.io/v2/{ip}?vpn=1&risk=1` | `proxy`/`vpn: yes`, тип Tor, `risk ≥ 67` → `no`; детали: тип и риск |
| ipapi.is | **нужен** `ipapi_is_key`: без ключа API отдаёт только гео, без флагов | `GET api.ipapi.is/?q={ip}` | `is_vpn`, `is_proxy`, `is_tor`, `is_abuser` → `no`; заметки: дата-центр, тип компании |
| AbuseIPDB | **нужен** `abuseipdb_key` | `GET api.abuseipdb.com/api/v2/check` (ключ в заголовке `Key`) | `isTor` или `abuseConfidenceScore ≥ 25` → `no`; заметки: число жалоб за 90 дней, тип использования |
| IPQualityScore | **нужен** `ipqs_key` | `GET ipqualityscore.com/api/json/ip/<key>/{ip}` | VPN, Tor, прокси, `recent_abuse`, `bot_status`, `fraud_score ≥ 75` → `no` |
| ipdata | **нужен** `ipdata_key` | `GET api.ipdata.co/{ip}?fields=…&api-key=` | `threat.*`: Tor, прокси, известный атакующий/абьюзер → `no`; заметки: дата-центр, iCloud Private Relay, блок-листы |

Ключ IPQS стоит в пути запроса, а не в query-строке; чтобы он не попал в журнал и ошибки, cii не выводит URL этого запроса целиком. Остальные ключи вычищаются стандартным `StripSecrets`.

## DNSBL

Запросы идут через системный резолвер (`netx.LookupHost`), каждая зона — одно обращение `reversed-ip.<зона>`; IPv6 — в nibble-формате для зон, которые его поддерживают. Параллельность ограничена восемью. Список зон короткий и состоит только из тех, чьи условия допускают бесплатные запросы:

| Зона | Что ловит | Особенности |
|---|---|---|
| `zen.spamhaus.org` | SBL, CSS, XBL, PBL | **не опрашивается через публичные резолверы** (8.8.8.8, 1.1.1.1, 9.9.9.9 и т.п. — Spamhaus на такие запросы отвечает заглушкой `127.255.255.x` и считает их нарушением). cii читает `/etc/resolv.conf`; если резолвер публичный, зона помечается `?` с пояснением |
| `bl.spamcop.net` | жалобы пользователей SpamCop | |
| `psbl.surriel.com` | PSBL | |
| `bl.mailspike.net` | репутация Mailspike | коды `127.0.0.10–14` — уровни репутации, в список не засчитываются |
| `dnsbl.dronebl.org` | боты, прокси, скомпрометированные узлы | в деталях расшифровывается тип (`SOCKS proxy`, `botnet`, …) |
| `dnsbl-1.uceprotect.net` | UCEPROTECT уровень 1 | |
| `all.s5h.net` | s5h.net | |

Ответ `NXDOMAIN` — «не в списке» (`yes`), `127.0.0.2+` — «в списке» (`no`) с расшифровкой кода, `127.255.255.x` — отказ оператора (`?`, никогда не «чисто»), таймаут — `!`. Большой список IPQuality (400+ зон) сознательно не переносится: большинство этих зон мертвы, у части платные условия, и массовый опрос нарушает FUP.

## Почта (группа Mail)

`Outbound SMTP (25)`: TCP-соединение к `gmail-smtp-in.l.google.com:25` (цель настраивается), чтение баннера, `QUIT`. Баннер `220` → `yes`; отказ, сброс или таймаут → `no` с причиной. Это ответ на вопрос «может ли этот хост отправлять почту напрямую», не более.

## Известные диапазоны (группа Network, офлайн)

Данные скачиваются только командой `cii data update` (по умолчанию вместе с базами DB-IP) и только у первоисточников; при проверке cii в сеть за ними не ходит. Формат хранения — `data/risk/<id>.txt`: по одной строке `CIDR<TAB>подпись`, плюс `manifest.json` с датой, размером, sha256 и числом префиксов. Идентификаторы для `cii data update`: `risk:tor-exits`, `risk:aws`, `risk:gcp`, `risk:oracle`, `risk:cloudflare`, `risk:digitalocean`.

| Источник | Что | Лицензия/условия |
|---|---|---|
| `check.torproject.org/torbulkexitlist` | выходные узлы Tor | публичные данные Tor Project |
| `ip-ranges.amazonaws.com/ip-ranges.json` | AWS по сервисам и регионам | публикуется AWS для allow-листов |
| `www.gstatic.com/ipranges/cloud.json` | Google Cloud по регионам | публикуется Google |
| `docs.oracle.com/…/public_ip_ranges.json` | Oracle Cloud | публикуется Oracle |
| `www.cloudflare.com/ips-v4`, `ips-v6` | Cloudflare | публикуется Cloudflare |
| `www.digitalocean.com/geo/google.csv` | DigitalOcean (geofeed RFC 8805) | публикуется DigitalOcean |

Попадание в Tor → `no`, в облако или CDN → `partial` с подписью (например, `AWS EC2 eu-central-1`), иначе `yes`. Если ни один список не скачан, строка не показывается.

## Прокси

При `--proxy` DNS-запросы и прямые TCP-соединения запрещены (они раскрыли бы реальный адрес), поэтому DNSBL и SMTP дают `?` с причиной; HTTP-проверки репутации работают через прокси как обычно.
