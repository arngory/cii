# Репутация адреса, DNSBL и почта

Модуль `risk` отвечает на вопрос «как этот адрес выглядит со стороны»: считают ли его VPN, прокси или дата-центром, числится ли он в чёрных списках рассылок, открыт ли исходящий 25-й порт, входит ли он в известные диапазоны Tor и облаков. Источники идей — [xykt/IPQuality](https://github.com/xykt/IPQuality) и его список DNSBL; в отличие от оригинала, ничего не идёт через серверы автора, а платные базы работают только с вашими ключами. Отключается флагом `--no-risk`; в режиме `--offline` остаётся только офлайн-часть.

Статусы: `yes` — чисто, `no` — есть флаги или адрес в списке, `partial` — адрес в диапазоне облака или CDN (это не плохо, но для многих сервисов такой адрес «серверный»), `?` — источник недоступен или не ответил по существу, `!` — ошибка.

## Репутация (группа Reputation)

| Сервис | Ключ | Запрос | Как читается |
|---|---|---|---|
| proxycheck.io | не нужен; `proxycheck_key` снимает дневной лимит | `GET proxycheck.io/v3/{ip}?tag=0` (API v3; `tag=0` — запрос не сохраняется в истории аккаунта) | `detections`: VPN, Tor, прокси, `compromised` или `risk ≥ 67` → `no`; детали: оператор VPN (`operator.name`), тип сети, риск и период обнаружений `first_seen…last_seen`; флаг хостинга — из `detections.hosting` |
| ipapi.is | **нужен** `ipapi_is_key`: без ключа API отдаёт только гео, без флагов | `GET api.ipapi.is/?q={ip}` | `is_vpn`, `is_proxy`, `is_tor`, `is_abuser` → `no`; заметки: дата-центр, тип компании |
| AbuseIPDB | **нужен** `abuseipdb_key` | `GET api.abuseipdb.com/api/v2/check` (ключ в заголовке `Key`) | `isTor` или `abuseConfidenceScore ≥ 25` → `no`; заметки: число жалоб за 90 дней, тип использования |
| IPQualityScore | **нужен** `ipqs_key` | `GET ipqualityscore.com/api/json/ip/<key>/{ip}` | VPN, Tor, прокси, `recent_abuse`, `bot_status`, `fraud_score ≥ 75` → `no` |
| ipdata | **нужен** `ipdata_key` | `GET api.ipdata.co/{ip}?fields=…&api-key=` | `threat.*`: Tor, прокси, известный атакующий/абьюзер → `no`; заметки: дата-центр, iCloud Private Relay, блок-листы |

Ключ IPQS стоит в пути запроса, а не в query-строке; чтобы он не попал в журнал и ошибки, cii не выводит URL этого запроса целиком. Остальные ключи вычищаются стандартным `StripSecrets`.

## Уровень B: страницы сервисов без ключа (`--extended`)

Экспериментальный режим для тех, у кого нет ключей. cii берёт данные так же, как их видит посетитель сайта: один запрос на сервис за запуск, честный User-Agent, без обхода капчи и без чужих ключей. Это не публичные API: условия сайтов обычно не рассчитаны на автоматические запросы, а формат может поменяться без предупреждения. Тогда проверка покажет `?` или `!`, остальные результаты от этого не пострадают. Проверки помечены `*`, как и остальной уровень B.

| Сервис | Запрос | Что берётся |
|---|---|---|
| ipinfo.io | `GET ipinfo.io/widget/demo/{ip}` — JSON демо-виджета с сайта | флаги `privacy` (VPN, прокси, Tor, хостинг, relay), тип ASN и компании, мобильная сеть |
| Scamalytics | `GET scamalytics.com/ip/{ip}` — страница проверки адреса (HTML) | Fraud Score и уровень риска, строки VPN, Tor, Server, Public/Web/Residential Proxy, Search Engine Robot, внешние списки (Firehol, IP2ProxyLite, IPsum, Spamhaus, X4Bnet) |
| ip2location.com | `GET www.ip2location.com/`, затем `POST api.ip2location.io/query/` | главная страница показывает посетителю его собственный адрес: cii берёт из неё одноразовый токен страницы и запрашивает тем же способом, что и её скрипт (без заголовков `Origin` и `Referer`: сервис отвечает и без них), только для проверяемого адреса (если страница показывает другой, проверка даёт `?`). Usage Type, Fraud Score, Is Proxy и тип прокси (VPN, TOR, DCH — дата-центр, SES — поисковый робот, остальные — прокси), Security Threat. Путь проверен только по разметке страницы, а не прогоном против сайта; если сервис не примет запрос без заголовков браузера, проверка даст `?` |

Не включены: AbuseIPDB и DB-IP (страницы закрыты проверкой Cloudflare), IPQualityScore (страница проверки закрыта капчей), ipdata и ipregistry (демо на сайтах работает через ключ, вшитый в страницу, — это чужой ключ).

## Профиль адреса

Разделы 1–4 отчёта IPQuality (страна регистрации и совпадение с геолокацией, тип адреса, оценки риска, факторы риска) cii собирает из ответов, которые и так получает: GeoIP-провайдеров из модуля `region` и источников репутации выше. Отдельных запросов профиль не делает.

| Источник | Ключ | Тип | Оценка | Флаги |
|---|---|---|---|---|
| RDAP (RIR) | — | — | — | страна регистрации |
| ipquery.io | — | мобильная сеть | `risk_score` | прокси, VPN, Tor, хостинг |
| ip2location.io | необязательно | — | — | прокси |
| ip-api.com | — | мобильная сеть | — | прокси, хостинг |
| proxycheck.io | необязательно | тип из ответа (Residential, Business, Wireless, Hosting) | `risk` | прокси, VPN, Tor, хостинг |
| ipapi.is | нужен | `asn.type`, тип компании | `abuser_score` × 100 | прокси, VPN, Tor, хостинг, абьюзер, бот |
| AbuseIPDB | нужен | `usageType` | `abuseConfidenceScore` | Tor, абьюзер (оценка ≥ 25) |
| IPQualityScore | нужен | `connection_type` | `fraud_score` | прокси, VPN, Tor, абьюзер (`recent_abuse`), бот |
| ipdata | нужен | `asn.type` | `threat_score`, если есть в ответе | прокси, VPN (если есть в ответе), Tor, хостинг, абьюзер |
| ipregistry.co | нужен | тип подключения, тип компании | — | прокси, VPN, Tor, облако, абьюзер |
| ipinfo.io (уровень B) | — | тип ASN и компании, мобильная сеть | — | прокси, VPN, Tor, хостинг |
| Scamalytics (уровень B) | — | тип подключения | Fraud Score | прокси, VPN, Tor, хостинг, абьюзер (внешние списки), бот |
| ip2location.com (уровень B) | — | Usage Type | Fraud Score | прокси, VPN, Tor, хостинг, бот, абьюзер (Security Threat) |

Типы приводятся к одному набору: ISP, mobile, hosting, business, education, government, CDN. Оценки — от 0 до 100, чем больше, тем хуже. Уровень (very low … very high) у каждой базы свой: где база называет его сама, берётся её название (Scamalytics: `risk`, ipapi.is: подпись в `abuser_score`); где публикует пороги — её пороги (proxycheck.io: 34 и 67; IPQualityScore: 75 «suspicious», 85 «high», 90; AbuseIPDB: 25, 75, 100); у остальных — общая шкала 10/25/50/75. Поэтому IPQS 62 — это low, а proxycheck 62 — medium. Флаг засчитывается источнику, только если тот действительно о нём сообщил: «прокси 1/4» значит, что о прокси высказались четыре источника и один его нашёл.

Страна регистрации берётся из RDAP и в вердикт страны не входит. Если она совпадает с вердиктом, адрес помечается `geo-consistent`, иначе `geo-discrepant` (в IPQuality — «原生IP» и «广播IP»): так обычно выглядят адреса, которые зарегистрированы в одной стране, а анонсируются и используются в другой.

На экране профиль занимает левую панель «IP quality»: адрес, ASN и место, страна регистрации с пометкой и три секции по источникам — **Type** (цветные метки ISP, MOB, BIZ, EDU, GOV, HOST, CDN для типа адреса и компании), **Score** (оценка, полоска из пяти делений и уровень по шкале этой базы) и **Factors** (страна по мнению источника и флаги). Под таблицей остаются только источники репутации, которые что-то нашли, не ответили по существу или вернули ошибку; чистые ответы уже учтены в таблице. Таблица по каждому источнику — в `--debug` («IP profile»), в JSON — поле `profile` у адреса и `facts` у каждой проверки.

Без ключей профиль строится по ipquery.io, ip2location.io, ip-api.com, proxycheck.io и RDAP: страна регистрации, тип адреса от proxycheck.io (и «mobile» от ipquery.io и ip-api.com), две оценки и флаги прокси, VPN, Tor и хостинга. Тип компании, флаги абьюзера и бота дают только источники с ключами.

## DNSBL

Запросы идут через системный резолвер (`netx.LookupHost`), каждая зона — одно обращение `reversed-ip.<зона>`; IPv6 — в nibble-формате для зон, которые его поддерживают. Параллельность ограничена восемью. Список зон короткий и состоит только из тех, чьи условия допускают бесплатные запросы:

| Зона | Что ловит | Особенности |
|---|---|---|
| `zen.spamhaus.org` | SBL, CSS, XBL, PBL | **не опрашивается через публичные резолверы** (8.8.8.8, 1.1.1.1, 9.9.9.9 и т.п. — Spamhaus на такие запросы отвечает заглушкой `127.255.255.x` и считает их нарушением). cii читает `/etc/resolv.conf`; если резолвер публичный, зона помечается `?` с пояснением |
| `bl.spamcop.net` | жалобы пользователей SpamCop | |
| `psbl.surriel.com` | PSBL | |
| `bl.mailspike.net` | репутация Mailspike | коды `127.0.0.10–14` — уровни репутации, в список не засчитываются |
| `dnsbl.dronebl.org` | боты, прокси, скомпрометированные узлы | в деталях расшифровывается тип (`SOCKS proxy`, `botnet`, …) |
| `dnsbl-1.uceprotect.net` | UCEPROTECT уровень 1 | |
| `all.s5h.net` | s5h.net | |

Ответ `NXDOMAIN` — «не в списке» (`yes`), `127.0.0.2+` — «в списке» (`no`) с расшифровкой кода, `127.255.255.x` — отказ оператора (`?`, никогда не «чисто»), таймаут — `!`. Большой список IPQuality (400+ зон) сознательно не переносится: большинство этих зон мертвы, у части платные условия, и массовый опрос нарушает FUP.

## Обратный DNS (группа Network)

`Reverse DNS`: PTR-запись проверяемого адреса через системный резолвер (`netx.LookupAddr`, правила `*.in-addr.arpa` и `*.ip6.arpa`; в журнал попадает только шаблон, не адрес). Имя хоста показывается строкой `PTR` в панели «IP quality»: по нему часто видно тип адреса (`dsl-…`, `pool-…`, `static-…`, облачные имена). Нет записи — `?` «no PTR record». С `--mask` имя скрывается целиком, потому что в нём часто записан сам адрес. При прокси запрос не выполняется.

## Почта (группа Mail)

`Outbound SMTP (25)`: TCP-соединение к `gmail-smtp-in.l.google.com:25` (цель настраивается), чтение баннера, `QUIT`. Баннер `220` → `yes`; отказ, сброс или таймаут → `no` с причиной. Это ответ на вопрос «может ли этот хост отправлять почту напрямую», не более.

## Известные диапазоны (группа Network, офлайн)

Данные скачиваются только командой `cii data update` (по умолчанию вместе с базами DB-IP) и только у первоисточников; при проверке cii в сеть за ними не ходит. Формат хранения — `data/risk/<id>.txt`: по одной строке `CIDR<TAB>подпись`, плюс `manifest.json` с датой, размером, sha256 и числом префиксов. Идентификаторы для `cii data update`: `risk:tor-exits`, `risk:aws`, `risk:gcp`, `risk:oracle`, `risk:cloudflare`, `risk:digitalocean`, `risk:spamhaus-drop`, `risk:peeringdb`. У PeeringDB формат другой: строка `AS<номер><TAB>типы сети`.

| Источник | Что | Лицензия/условия |
|---|---|---|
| `check.torproject.org/torbulkexitlist` | выходные узлы Tor | публичные данные Tor Project |
| `ip-ranges.amazonaws.com/ip-ranges.json` | AWS по сервисам и регионам | публикуется AWS для allow-листов |
| `www.gstatic.com/ipranges/cloud.json` | Google Cloud по регионам | публикуется Google |
| `docs.oracle.com/…/public_ip_ranges.json` | Oracle Cloud | публикуется Oracle |
| `www.cloudflare.com/ips-v4`, `ips-v6` | Cloudflare | публикуется Cloudflare |
| `www.digitalocean.com/geo/google.csv` | DigitalOcean (geofeed RFC 8805) | публикуется DigitalOcean |
| `www.spamhaus.org/drop/drop_v4.json`, `drop_v6.json` | Spamhaus DROP: угнанные и отданные под спам или киберпреступность сети | бесплатно по условиям Spamhaus DROP |
| `www.peeringdb.com/api/net?fields=asn,info_types` | тип сети по ASN (Cable/DSL/ISP, NSP, Content, Enterprise, Educational/Research, Government…) | правила PeeringDB: для своих целей (диагностика, исследование сети), данные нельзя передавать другим оптом — поэтому cii только скачивает их по вашей команде и не встраивает в сборки |

Попадание в Tor или Spamhaus DROP → `no`, в облако или CDN → `partial` с подписью (например, `AWS EC2 eu-central-1`), иначе `yes`. Проверяются только списки, которые есть в `manifest.json` и чьи файлы на месте; в чистом результате они перечислены («not in: tor-exits, aws, …»). Если ни один список не скачан, строка не показывается.

PeeringDB работает иначе: по ASN адреса из локальной базы (DB-IP ASN или IPinfo Lite) находится тип сети, он попадает строкой `PeeringDB` в секцию Type панели «IP quality» (Cable/DSL/ISP и NSP → ISP, Content и Network Services → HOST, Enterprise и Non-Profit → BIZ, Educational/Research → EDU, Government → GOV). Это единственный тип адреса, который cii знает без сети и ключей. FireHOL не подключается: его наборы собраны из списков с разными, местами несовместимыми условиями; самый полезный из них по смыслу, Spamhaus DROP, берётся напрямую у Spamhaus.

## Прокси

При `--proxy` DNS-запросы и прямые TCP-соединения запрещены (они раскрыли бы реальный адрес), поэтому DNSBL и SMTP дают `?` с причиной; HTTP-проверки репутации работают через прокси как обычно.
