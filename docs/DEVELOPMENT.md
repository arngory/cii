# Разработка

## Сборка и проверки

```bash
make check
```

```bash
make build
```

```bash
make cross
```

`make check` запускает gofmt, `go vet` и тесты. `make cross` собирает все целевые платформы в `dist/` и пишет `SHA256SUMS`. Нужен Go той версии, что указана в `go.mod`. Для сборки без сети заранее выполните `go mod vendor`.

Тесты не ходят в интернет: HTTP проверяется на `httptest`, базы — на синтетических записях.

Встроенные справочники обновляются вручную:

```bash
go generate ./internal/refdata
```

Генератор `tools/gendata` — инструмент разработчика: он не входит в бинарник `cii` и потому обращается к CLDR и OurAirports напрямую через `net/http`, без `internal/netx`.

## Релизы

Тег `v*` запускает `.github/workflows/release.yml`:

1. проверки и кросс-сборка;
2. загрузка DB-IP Lite самим `cii data update` напрямую у издателя;
3. если в репозитории задан секрет **`IPINFO_TOKEN`** — ещё и IPinfo Lite;
4. `go run ./tools/notices` собирает `THIRD_PARTY_LICENSES.txt` (лицензии стандартной библиотеки Go, всех модулей, которые попадают в бинарник, и встроенных справочников) и `DATA-NOTICE.txt` (атрибуция, лицензия со ссылкой, дата сборки и sha256 для каждой приложенной базы, по манифесту и реестру источников);
5. пакеты deb, rpm и apk (в них кладётся и `THIRD_PARTY_LICENSES.txt`);
6. публикация релиза с бинарниками, пакетами, `*.mmdb.gz`, `data-manifest.json`, обоими файлами уведомлений и `SHA256SUMS`. Если релиз для тега уже создан вручную, файлы догружаются в него, а пустое описание заменяется шаблоном `docs/RELEASE_NOTES_TEMPLATE.md`.

7. обновление `Formula/cii.rb` и `bucket/cii.json` в ветке `main` отдельным коммитом от `github-actions[bot]` — по ним работают `brew tap arngory/cii https://github.com/arngory/cii` и `scoop bucket add cii https://github.com/arngory/cii`. Для предварительных версий (тег с дефисом) шаг пропускается. Шаг не валит релиз: если ветка защищена от прямых пушей, файлы нужно обновить вручную из приложенных к релизу `cii.rb` и `cii.json`.

`PKGBUILD` для AUR прикладывается к релизу, но не публикуется: для AUR нужна учётная запись и SSH-ключ владельца пакета.

Генератор отказывается работать, если у модуля не найден файл лицензии или у базы нет атрибуции или ссылки на лицензию: новая зависимость без лицензии остановит релиз, а не уйдёт без уведомления.

Секрет добавляется в Settings → Secrets and variables → Actions → New repository secret. Имя: `IPINFO_TOKEN`, значение: токен с https://ipinfo.io/dashboard. Внутри workflow токен передаётся в `CII_IPINFO_TOKEN` и не попадает в манифест.

## Перевод документации

Источник — русские документы в `docs/`. Английские версии пользовательских документов лежат в `docs/en/` под теми же именами: CONFIG, NETWORK_POLICY, REGION_CHECKS, SERVICE_CHECKS, RISK_CHECKS, CENSOR_CHECKS, ROUTE, BENCH, DATA_SOURCES. При правке русского документа тот же абзац правится в английском. Структура (заголовки, таблицы, списки) в обеих версиях одинаковая, чтобы их можно было сверять построчно. Документы для разработчиков и каталоги сервисов не переводятся.

## Цикл ревью (Stop-хук Claude Code)

В `.claude/settings.json` зарегистрирован Stop-хук `.claude/hooks/review-on-stop.sh`. Когда Claude Code пытается завершить ответ, хук:

1. собирает diff кода (`*.go`, `go.mod`, `go.sum`, `Makefile`, `*.sh`, workflows) относительно `origin/main`, включая неотслеживаемые файлы;
2. если diff пуст или уже был признан чистым (сравнение по sha256), пропускает остановку;
3. иначе запускает отдельного ревьюера через `claude -p` с инструкцией из `.claude/hooks/review-prompt.md`; ревьюер может читать репозиторий и запускать `go build/vet/test` и `gofmt`;
4. при `VERDICT: ISSUES` блокирует остановку и возвращает замечания; Claude исправляет их, и при следующей попытке остановиться ревью повторяется;
5. при `VERDICT: CLEAN` запоминает хэш diff и пропускает остановку.

Ревью касается только кода: комментарии и документация не оцениваются. Защита от бесконечного цикла: не больше `CII_REVIEW_MAX_ROUNDS` раундов подряд (по умолчанию 12). Если CLI `claude` недоступен или ревьюер не вернул вердикт, остановка разрешается с предупреждением. Вложенный ревьюер запускается с отключёнными хуками и `CII_REVIEW_HOOK=1`, чтобы не вызвать хук рекурсивно. Состояние хранится в `.claude/review-state/` (в `.gitignore`).

Ручной запуск того же ревью:

```bash
echo '{}' | CLAUDE_PROJECT_DIR=$PWD .claude/hooks/review-on-stop.sh
```

## Стиль

- Код без поясняющих комментариев: объяснения пишутся в `docs/`.
- Вся сеть — только через `internal/netx`; каждый новый хост — это правило политики с указанием назначения.
- Проверки сервисов — с указанием уровня (A/B) и источника идеи.

## Фаззинг

`make fuzz` (по умолчанию 30 секунд на цель, `FUZZTIME=5m make fuzz` — дольше) гоняет разбор ответов всех проверок регионов, сервисов, каталогов и риска на произвольных телах, статусах и заголовках, а также парсеры офлайн-списков, вывода fio и DNS-ответов цензуры. Начальные примеры прогоняются и в обычном `go test`. Найденные падения Go сохраняет в `testdata/fuzz/` пакета — такой файл стоит закоммитить вместе с исправлением.
