# Как устроен и подключается модуль

Документ для разработчиков модулей cii. Общие правила — в [NETWORK_POLICY.md](NETWORK_POLICY.md), устройство — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Обязательные правила

1. **Сеть — только через `internal/netx`.**
   - HTTP: `n.HTTPClient(module)`.
   - TCP/UDP: `n.Dial(ctx, module, network, addr)`.
   - DNS через системный резолвер: `n.LookupHost(ctx, module, name)`.
   - Прямые `net.Dial`, `http.Get`, `net.DefaultResolver` и т.п. в модулях запрещены; исключение — генераторы в `tools/`, которые не входят в бинарник.
2. **Каждый адрес объявляется заранее** функцией модуля `Rules(...) []netx.Rule`: точный хост или `*.suffix`, с понятным `Purpose`. Необъявленное блокируется и попадает в журнал как `BLOCKED`.
3. **При прокси (флаг или окружение) сырые соединения и DNS запрещены** (`netx.ErrProxyRaw`) — модуль сообщает об этом как о результате, а не падает. `n.Dial` к имени хоста разрешает это имя системным резолвером внутри `net.Dialer`; это разрешённый побочный запрос к объявленному хосту, отдельно в журнал он не пишется.
4. **Модуль ничего не печатает.** Он возвращает данные (`[]probe.Result` или свою структуру с JSON-тегами); вывод делает `internal/report`.
5. **Никаких удалённых зависимостей.** Модуль не скачивает и не запускает код и бинарники, не отправляет результаты, не использует чужие ключи. Внешние программы (iperf3, fio, speedtest) — только если уже установлены и только по флагу, с подсказкой установки при отсутствии.
6. **Уровни проверок** — по [NETWORK_POLICY.md](NETWORK_POLICY.md): A по умолчанию, B только с `--extended` (идентификаторы клиентов — только в `internal/clientids`), C не реализуется.
7. **Нагрузка.** Один-два запроса на проверку за запуск, ограниченная параллельность, без повторов-штормов; таймауты — из `n.Options().Timeout`.
8. **Код без поясняющих комментариев**, проза — в `docs/`. Тесты не ходят в сеть: `httptest`, локальные слушатели, записанные ответы.
9. **Зависимости.** Без согласования новых модулей в `go.mod` не добавлять; стандартной библиотеки и `golang.org/x/net`, `golang.org/x/sys`, `golang.org/x/term` достаточно.

## Проверки на движке `probe`

`probe.Check` описывает запросы (`Requests`), уровень (`Tier`), необязательный ключ пользователя (`KeyOK`, `Authorize`) и функцию оценки `Eval([]*probe.Response) []probe.Result`. Статусы: `ok` (страна), `yes`, `no`, `partial`, `ipblock`, `unknown`, `error`. Для дополнительной информации есть поле `Detail`.

Региональный каталог сервисов пополняется из файла `internal/services/region_<код>.go`:

```go
func init() {
	register("JP",
		probe.Check{Service: "ABEMA", Requests: probe.Get("https://…"), Eval: abema},
	)
}
```

Группа проставляется автоматически по коду каталога; страны каталога заданы в `internal/services/regional.go`.
